## F1. W5 plate rules (issue 3)

Files/functions: `R/validate.R` (`umg_validate()`), `R/utils.R`
(`.umg_plates_of()`), `R/constructors.R` (`umg_edge()`).

New behaviour. After the existing W5 coherence checks (members
declared, parent declared, nesting acyclic), `umg_validate()` now
enforces:

* (b) nesting membership: every vertex of a plate nested inside
  another plate must also belong to the parent plate; otherwise
  `W5 violated: vertex 'y' is in plate 'occasion' but not in its
  parent plate 'cluster'.`
* (c) index licensing: for every `dep` and `det` edge u -> v,
  plates(u) must be a subset of plates(v); otherwise
  `W5 violated: edge u -> v is not licensed by the index structure
  (plates of 'u' are not contained in the plates of 'v').` A `det`
  edge created with `umg_edge(..., aggregate = TRUE)` (new argument,
  default `FALSE`; an error on non-`det` edges) is exempt, for
  deterministic aggregates such as a cluster mean. For `cov` edges the
  plate sets must be equal: `W5 violated: cov edge u <-> v joins
  vertices with different plate membership.`
* (d) mixing: for a `mix` edge from c, every random vertex w that is a
  `dep`-child of the mix target must satisfy plates(c) within
  plates(w); otherwise `W5 violated: mix edge from 'c' selects a
  parameter used by 'w', which is not replicated over the plates of
  'c'.` The mix target itself is exempt from (c) (it denotes a
  K-vector selected per copy of c), so `umg_mixture()`'s class inside
  the person plate selecting a parameter outside all plates is legal.

The three reproductions of issue 3 are now refused with exactly the
messages above ((a) nesting membership; (b) inner-plate y_t ->
outer-plate b0_i; (c) item-plate a_j -> person-plate theta_i in
`umg_irt("2PL")`), and the demo_validate cases e1-e3 flip from
ACCEPTED to REFUSED.

Builders checked under the new rules (all validate; none changed):

## F2. Counting rule with `meanstructure = TRUE` (issue 1)

Files/functions: `R/identify.R` (`umg_count_parameters()`,
`umg_identify()`), `R/utils.R` (`.umg_free_means()`).

New behaviour. 0.5.0 counted one free mean per random vertex
(Demo.growth: 14 moments, 13 free, df = 1). The free means are now
counted as documented: if every random vertex carries a mean
annotation (`mean = free` / `mean = 0` / `mean = <value>` /
`mean = fixed`, written by `umg_from_lavaan()` from a fit with a mean
structure, see F7), the vertices annotated `mean = free` are counted;
otherwise the growth-model convention applies (indicators of latent
factors have zero intercepts; free means = latent source vertices +
observed vertices not regressed on a latent vertex). Demo.growth now
returns 14 moments, 9 free, df = 5 by both routes
(`umg_from_lavaan(fit_gr)` and `umg_growth(4)`), matching lavaan's
`growth()` (npar 9, df 5). The Rd states the convention precisely and
documents the new override `n_means = NULL` (also accepted by
`umg_identify()`): for a CFA fitted with free observed intercepts and
zero latent means, `n_means = p` leaves the df unchanged. The
annotation route reproduces lavaan exactly for that case as well
(HS CFA with `meanstructure = TRUE`: 9 free means, df 24).

Limitation documented rather than silently wrong: for a
hand-built diagram the convention is an assumption; the growth
convention is the one lavaan's `growth()` uses, and other conventions
need `n_means`.

Tests: "the counting rule reproduces lavaan's growth-model df with a
mean structure (issue 1)" and "the counting rule reads mean
annotations from a lavaan fit (issues 1 and 14)".

## F3. `umg_implied_ci()` de-duplication (issue 2)

Files/functions: `R/identify.R` (`umg_implied_ci()`, new internal
`.umg_n_ci()`, `print.umg_identification()`).

New behaviour. Each statement is returned once in canonical form: `x`
precedes `y` in the model's vertex order and the conditioning set is
listed in vertex order; row names are reset to 1..n. The mediation
diagram with a confounder returns the single row `X U |` (0.5.0: `X U`
and `U X`); the one-factor model with four indicators returns 6 rows
(0.5.0: 12). `print.umg_identification()` counts distinct unordered
statements, so it is correct even for an implied-CI table built
elsewhere that still carries both orientations.

Tests: "umg_implied_ci lists each symmetric statement once (issue 2)".

## F4. Scaling check (issue 5) and `umg_formative()` (issue 4)

Files/functions: `R/identify.R` (`umg_check_scaling()`),
`R/motifs_extra.R` (`umg_formative()`).

New behaviour. A constant parent no longer counts as a scaling mark
(it fixes the location, not the scale). `via` is one of `"marker
loading"`, `"fixed variance"`, `"marker weight"`, or `"none"`; the
fourth value is the formative case, a unit-valued incoming `dep` edge
from an observed cause, which fixes the composite's scale to that
cause's scale (the marker convention lavaan applies to `<~`
composites). A new informational column `location_fixed` reports
whether a constant parent is present. The issue-5 diagram now reports
`scaled = FALSE, via = "none", location_fixed = TRUE` and
`umg_identify()` prints `UNSCALED: F`.

`umg_formative()` fixes the weight of the first indicator to 1 by
default (new argument `scaling = c("marker", "none")`, documented;
`"none"` reproduces the 0.5.0 unscaled drawing). The default motif
(four causes, two outcomes) passes `umg_check_scaling()`
(`via = "marker weight"`) and counts 12 free parameters, df = 9
(0.5.0: 13 free, df = 8, flagged as unscaled).

Tests: "a constant parent fixes the location, not the scale (issue
5)" and "umg_formative scales the composite by a marker weight (issue
4)". The pre-existing scaling tests in `test-identify.R` and
`test-regressions-050.R` pass unchanged.

## F5. DOT export (issues 7 and 8)

Files/functions: `R/dot.R` (`.umg_dot_edge_attr()`, `umg_to_dot()`),
`R/utils.R` (`.umg_plate_within()`).

New behaviour. Covariance edges are written as `dir=both,
arrowhead=normal, arrowtail=normal, constraint=false` (no
`style=curved`, which Graphviz rejected with "unsupported style
curved" on every covariance edge). The note `// note: crossed plates
rendered by smallest-enclosing assignment` is emitted only when a
vertex belongs to two plates neither of which encloses the other
(persons x items in `umg_irt()`), and no longer for nested plates
(the sleepstudy diagram from `umg_from_lmer()`). The Graphviz CLI now
renders both demonstration diagrams without any warning.

Tests: "umg_to_dot emits no style=curved and flags only crossed
plates (issues 7 and 8)".

## F7. Mean structure through the converters (issue 14)

Files/functions: `R/converters.R` (`.umg_build_partable()`, used by
`umg_from_lavaan()` and `umg_from_blavaan()`), `R/export_model.R`
(`umg_to_lavaan()`), `R/utils.R` (`.umg_mean_annot()`,
`.umg_annot_add()`).

New behaviour. `~1` rows of the parameter table become annotations on
the vertex's `annot` field: `mean = free` (free row), `mean = <ustart>`
(fixed with a start value, e.g. `mean = 0`), or `mean = fixed` (fixed
with no start value, i.e. fixed at a sample quantity under lavaan's
`fixed.x = TRUE`). `umg_to_lavaan()` emits an `# intercepts / means`
block: `v ~ 1` for `free`, `v ~ <value>*1` for a value, and nothing
for `fixed` (a refit under `fixed.x = TRUE` fixes it the same way, and
an explicit line would turn the covariate endogenous and change the
df). Verified on Demo.growth: the emitted syntax refitted with `cfa()`
gives npar 9, df 5, chi-square 8.068734, identical to the `growth()`
fit (0.5.0: cfa() refit df = 3). Fits without a mean structure (the
HS CFA) produce byte-identical syntax to 0.5.0. Annotations combine
with existing ones (`2 thresholds; mean = 0`, `mean = free; prior`);
the Bayesian converters now append `prior` instead of skipping
vertices that already carried an annotation.

Tests: "the mean structure of a growth model round-trips through
cfa() (issue 14)" and "mean annotations combine with existing
annotations".
